## 三、突破点：GitHub 数据集可完整下载

### 3.1 下载方法

关键是加 `Accept: application/vnd.github.raw` 头（避开 base64 膨胀）：

```js
const r = await fetch(
  'https://api.github.com/repos/docyx/pc-part-dataset/contents/data/json/video-card.json',
  { headers: { 'User-Agent': 'x', Accept: 'application/vnd.github.raw' } }
);
const arr = JSON.parse(await r.text());
```

### 3.2 实测下载结果（全部成功）

| 品类 | 记录数 | 体积 | 耗时 |
|---|---:|---:|---:|
| gpu (video-card) | 6,636 | 1002 KB | 20.1s |
| motherboard | 4,973 | 691 KB | 12.4s |
| cpu | 1,413 | 219 KB | 1.8s |
| memory | 13,553 | 2222 KB | 43.1s |
| psu | 3,438 | 421 KB | 6.8s |
| case | 6,626 | 1071 KB | 22.2s |

> 数据已存于 `tmp-ds/`（被 `.gitignore` 的 `tmp-*` 覆盖，不会误提交）

### 3.3 为什么这次能用而 v1 不能

v1 时我用 GitHub **contents API（默认 base64）**取 1MB 文件，60s 超时。
本次改用 `Accept: application/vnd.github.raw` 拿原始文本，25s 完成 —— **方法问题，不是网络问题**。

### 4.1 数据集字段（关键）

```

chipset  = "GeForce GTX 1660 SUPER"    ← 芯片名（在 chipset 字段，不在 name）
length   = 204                          ← 真实板卡长度（mm）
price, memory, core_clock, boost_clock, color
```

### 4.4 字段可获取性分析

| 字段 | 来源 | 可靠性 |
|---|---|---|
| `chipset` | 数据集 | ✅ 准确 |
| `length` | **数据集（真实值）** | ✅ **比现有数据更准** |
| 品牌 | 从 `name` 解析 | ✅ 98% |
| 型号名 | `name` | ✅ |
| `tdp` / `vram` / `pcieVersion` / `memoryType` | 本项目已有数据的**芯片级参照表** | ✅ 实测 7/7 芯片完全一致 |
| `gameScore` / `productivityScore` | 同上 | ✅ 7/7 一致 |
| `pcie12vhpwr` | 同上 | ✅ 7/7 一致 |
| `pcie8pin` | 同上 | ⚠️ 6/7 一致（RTX 3060 Ti 出现 2/1 两种） |
| `thicknessSlots` | ❌ **无来源** | 长度与厚度无强相关，**不可推导** |

**thicknessSlots 实测反例**（长度无法推厚度）：

| 长度区间 | 厚度分布 |
|---|---|
| ≤180mm | 全部 2 槽 |
| 221-260mm | 2 槽(7) / 2.5 槽(6) |
| >300mm | 3 / 2.5 / 2.7 / 3.5 / 3.8 / 3.7 槽混杂 |

> 长卡也可能是 2 槽，短卡也可能 2.5 槽。
> **结论：`thicknessSlots` 必须标 `estimated` 或另找来源。**

## 五、主板：部分可行 ⚠️

### 5.1 数据集字段

```
name, price, socket, form_factor, max_memory, memory_slots, color
```

- `socket` 100% 有值 ✅
- `form_factor` 100% 有值 ✅
- **无 `chipset` 字段** —— 需从 `name` 提取

### 5.2 芯片组提取成功率：31%

实测 4,973 条中，**1,560 条（31%）** 能从 name 里提取出芯片组。

> 提取率取决于芯片组清单的完整度：用 42 个常见芯片组的短清单得 23%，
> 用含老平台/HEDT 的完整清单（70+ 个）得 **31%**。下表用完整清单统计。

**本项目 42 个芯片组中，39 个有覆盖**：

| 覆盖情况 | 数量 | 芯片组 |
|---|---:|---|
| 覆盖充足（≥5 条） | 34 | Z790(125) Z690(83) Z97(62) Z590(57) B550(56) Z490(53) X570(49) X99(49) B760(49) Z390(48) Z170(44) B650(39) Z890(68) … |
| 覆盖偏少（1~4 条） | 5 | A520(1) B75(2) H61(2) A620(3) H81(4) |
| **完全无覆盖** | **3** | **A320、H610、H510** |

> 初版评估写「28%、5 个无覆盖」，是清单不全导致的偏差，此处已修正。

### 5.3 form_factor 取值需映射

数据集用 `Micro ATX` / `Mini ITX` / `EATX`，本项目枚举是 `M-ATX` / `Mini-ITX` / `E-ATX`，
需要一张映射表。

### 5.4 缺的字段（项目规则关键）

| 字段 | 用途 | 数据集 |
|---|---|---|
| `memoryType` | E2/E3 内存代数校验 | ❌ 无 |
| `maxMemorySpeed` | 内存兼容 | ❌ 无 |
| `pcieVersion` | 显卡/硬盘 PCIe 校验 | ❌ 无 |
| `m2Slots` | 硬盘接口校验 | ❌ 无 |
| `sataPorts` | 硬盘接口校验 | ❌ 无 |
| `cpuPowerConnectors` | 供电校验 | ❌ 无 |

**这些恰好是主板规则最依赖的字段。** 只能从 `chipset` 查表推导
（如 B650 → DDR5 + PCIe 4.0 + 通常 2×M.2），但**同芯片组不同主板可能有差异**，
可靠性低于显卡侧。

## 七、修正后的可行性判定

### 7.1 显卡（推荐立即执行）✅

| 项 | 判定 |
|---|---|
| 真实长度 | ✅ 可得（比现有数据更准） |
| 多品牌变体 | ✅ 54/62 芯片可覆盖，2162 条 |
| 芯片级字段 | ✅ 可 join（实测一致） |
| `thicknessSlots` | ⚠️ 无来源，标 `estimated` |
| `pcie8pin` | ⚠️ 逐条核对或标 `estimated` |

**做法**：
1. 从数据集按 chipset 取变体，**按长度去重后选 2~4 个有区分度的**（如最短/中/最长）
2. 芯片级字段从本项目现有数据建参照表 join
3. `thicknessSlots` 标 `estimated`
4. 保留现有 70 条，新增约 60~100 条

### 7.2 主板（谨慎执行）⚠️

| 项 | 判定 |
|---|---|
| socket / form_factor | ✅ 100% 可得 |
| chipset | ⚠️ 31% 可提取；42 个芯片组中 39 个有覆盖，3 个（A320/H610/H510）为零 |
| 规则关键字段 | ❌ 全部缺失（见 5.4） |

**做法**：用数据集补充**型号名 + socket + form_factor**，
其余字段按 chipset 查表推导并**全部标 `estimated`**；
或维持现状，只手工补少量确证的型号。

### 7.3 其它品类

CPU / 内存 / 电源 / 机箱 / 散热 / 硬盘**已达标**，无需补。
但数据集里也有，将来若需加深可复用同一方法。

## 八、建议

1. **先做显卡**（收益最高、可靠性最好）—— 直接用数据集真实长度，
   解决「同芯片不同品牌长度不同」这个核心痛点
2. **主板暂缓或小步走** —— 芯片组提取率 28%、规则字段全缺，
   强行补会产出一批字段靠猜的数据，反而降低可信度
3. **更新 `docs/数据扩充技术文档.md`** —— 把「联网不可用，只能凭知识填」
   改为「数据集可用，尺寸取真实值；thicknessSlots 标 estimated」
4. **保留 v1 的诚实标注原则** —— 凡推导/未知的字段一律进 `estimated`，
   界面显示 `≈`，用户可用 CSV 覆盖

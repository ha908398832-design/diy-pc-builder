## 2. 为什么补显卡/主板（而不是别的品类）

用户最初的两个诉求直接指向这两类：

1. **"配件库数量太少"** —— 显卡 70 条却只覆盖 8 个品牌，而实际市场有 20+ 个显卡品牌。
2. **"同一款显卡不同品牌长度不同"** —— 数据显示 GPU 芯片归并后 **89% 的芯片（55/62）只有 1 个变体**，
   点开没有第二个版本可选，用户根本感知不到"同芯片不同规格"这件事。

主板同理：81 条只有 **5 个品牌**，且芯片组虽有 42 个，但多数只有 1 个品牌 1 种板型。

| **P0** | **RTX 3060** | 1 | **3** | 二手热门，ITX 短卡多 |

| P1 | RX 580 / RX 590 | 1 各 | 3 各 | 二手主力 |
| P1 | RX 6600 / RX 7600 | 1 各 | 2 各 | 主流 |
| P2 | RTX 5070 / 5080 | 1 各 | 2 各 | 新品补充 |
| P2 | RTX 4070 Ti SUPER / 4080 | 1 各 | 2 各 | — |

**剩余名额**补齐其他单品牌芯片，每个 +1 个不同品牌的变体。

### 3.3 关键：必须体现形态差异

同一芯片的变体**必须有不同的 `length_mm`**，否则归并没有意义：

```
✅ 正确示例（GTX 1660 SUPER）
   微星   VENTUS OC          183mm  2槽   单风扇
   七彩虹 Ultra W OC        247mm  2槽   双风扇

   技嘉   WINFROST OC        202mm  2槽   单风扇

❌ 错误示例：三个变体都是 247mm（用户看不出差别，归并等于没做）
```

### 3.4 显卡字段要求

字段分两部分。

**① 通用字段**（`schema/fields.js` 的 `COMMON_FIELDS`，所有品类共享）：

| 字段 | 要求 |
|---|---|
| `id` | `gpu-<品牌英文小写>-<型号小写连字符>`，全局唯一 |
| `category` | 固定 `"gpu"` |
| `brand` | 中文品牌名 |
| `name` | 品牌 + 型号（含显存，如"微星 GTX 1660 SUPER VENTUS OC"） |
| `aliases` | ≥2 个常用简称，含芯片名 |
| `year` | 上市年份 |
| `condition` | 枚举 `new` / `used` / `mining` |
| `notes` | 说明形态特点（二手/矿卡须注明） |
| `estimated` | **凡非官方值必须列出**（含 `length_mm`） |

**② 品类字段**（`CATEGORY_FIELDS.gpu`，共 16 个，其中 10 个 `required: true`）：

| 字段 | 必填 | 要求 |
|---|---|---|
| **`chipset`** | ✅ | **归并键**，如 `"GTX 1660 SUPER"` |
| **`length_mm`** | ✅ | **真实长度**（归并显示的关键字段） |
| **`thicknessSlots`** | ✅ | 真实厚度（2 / 2.5 / 3 / 3.5 / 3.8） |
| `vram` | ✅ | 显存 GB |
| `tdp` | ✅ | 峰值功耗 W |
| `pcie8pin` | ✅ | 8pin 供电接口数 |
| `pcie12vhpwr` | ✅ | 12VHPWR 接口数 |
| `pcieVersion` | | 枚举 3 / 4 / 5（老平台可省略） |
| `gameScore` | | 以 R7 7800X3D = 100 为基准 |
| `productivityScore` | | 同上 |
| `memoryType` / `busWidth` / `height_mm` / `recommendedPsu` / `outputs` / `coolerType` | | 按实际填写，非关键字段 |

> ⚠️ **不得写 `price` 字段**（本期不做价格，由 `tools/check-no-price.mjs` 门禁强制）。

### 3.5 ⚠️ 数据可信度要求（重要）

当前 70 条显卡的 `length_mm` **全部未标 `estimated`**，但实际是凭知识填的
（GTX 1060 出现 175/242/290 三个值，证明并非同款实测尺寸）。

**本期新数据必须遵守**：

| 情况 | 做法 |
|---|---|
| 尺寸确定来自官方规格 | 正常填，**不列入** `estimated` |
| 尺寸是常见版本的典型值（不确定具体型号） | 填值**并列入** `estimated: ["length_mm", "thicknessSlots"]` |
| 完全不确定 | 不填该字段（归并时会显示 `—`），**不要瞎猜** |

界面会对 `estimated` 里的尺寸显示 `≈` 并提示"以实物规格为准"（PRD 3.1.3）。

> **本项目联网不可用**，`raw.githubusercontent.com` 与 `web_fetch` 均超时，
> API 凭据解决不了"连不上"的问题。所以采用「知识库填写 + 诚实标注 + CSV 覆盖」策略。
> 用户可通过 **导入 CSV**（M2 功能，项目已有）覆盖为实测值。

## 4. 主板扩充规格（81 → 130，需新增 49 条）

### 4.1 品牌扩充

当前仅 5 个品牌，需补：

`铭瑄 盈通 七彩虹 映众 冠铭 杰微 磐正 梅捷 精英 SOYO`

> 二手/洋垃圾主板可继续用 `华南金牌`（已有），它是该平台的主流选择。

### 4.2 归并键：芯片组 + 板型（重要）

主板归并**不是只按 chipset**，而是 `chipset·formFactor`：

```
B650·Mini-ITX   ← 独立成组（对应 ITX 机箱）
B650·M-ATX      ← 独立成组（对应中塔机箱）
B650·ATX        ← 独立成组（对应全塔机箱）
```

**原因**：Mini-ITX / M-ATX / ATX / E-ATX 是四种不同规格，对应完全不同的机箱。
混在一组会误导用户（v1.3 修复过这个 bug，详见 `docs/`）。

**所以补数据时，同一 `chipset` 不同 `formFactor` 算不同组**，
不要为了凑数量把不同板型填成同一个。

### 4.3 芯片组补全规则

按当前变体数排序，**每个芯片组补到 3~5 个变体**：

|---|---:|---:|---|
| B650·ATX | 2 | 4 | 铭瑄 盈通 七彩虹 |
| B650·Mini-ITX | 1 | 3 | 铭瑄 技嘉 华硕 |
| X670E·ATX | 2 | 4 | 映众 铭瑄 技嘉 |
| B650E·ATX | 1 | 3 | 铭瑄 盈通 |
| B450·M-ATX | 4 | 5 | 铭瑄 盈通 |
| B550·M-ATX | 3 | 5 | 铭瑄 盈通 七彩虹 |
| X570·ATX | 3 | 5 | 铭瑄 盈通 七彩虹 |
| B760·M-ATX | 3 | 5 | 铭瑄 盈通 映众 |
| H610·M-ATX | 2 | 4 | 铭瑄 七彩虹 |
| B660·M-ATX | 2 | 4 | 铭瑄 盈通 |
| Z690·ATX | 2 | 4 | 映众 铭瑄 |

### 4.4 主板字段要求

通用字段同显卡（`id` 用 `motherboard-` 前缀，`category` 为 `"motherboard"`）。

**品类字段**（`CATEGORY_FIELDS.motherboard`，共 18 个，其中 10 个 `required: true`）：

| 字段 | 必填 | 要求 |
|---|---|---|
| `socket` | ✅ | 枚举内取值，见附录 B |
| **`chipset`** | ✅ | 归并键之一，如 `"B650"` |
| **`formFactor`** | ✅ | 枚举 `E-ATX` / `ATX` / `M-ATX` / `Mini-ITX`，**归并键之二** |
| `memoryType` | ✅ | 枚举 `DDR3` / `DDR4` / `DDR5`，**必须与同 socket 的 CPU 兼容** |
| `memorySlots` | ✅ | 内存槽数（2~8） |
| `maxMemory` | ✅ | 最大容量 GB（老平台可能偏小） |
| `maxMemorySpeed` | ✅ | DDR3 1600~2133；DDR4 2133~3200；DDR5 4800~8000 |
| `pcieVersion` | ✅ | 枚举**只有 3 / 4 / 5**；老平台（B75/X58 等）填 3 |
| `pcieX16Slots` | ✅ | PCIe x16 插槽数（0~4） |
| `m2Slots` | ✅ | **老平台多为 0（合法值）** |
| `sataPorts` | ✅ | 老平台 2~6 |
| `cpuPowerConnectors` | ✅ | 8pin 等效数（注意与 `vrmPhases` 最小值 2 不冲突） |
| `vrmPhases` | | 供电相数，最小值 2 |
| `wifi` / `usbC` / `biosFlashback` | | 布尔 |
| `length_mm` / `width_mm` | | 板子尺寸（ITX 170×170，M-ATX 244×244，ATX 305×244） |

> ⚠️ `pcieVersion` 枚举里**没有 2**。B75/H61/X58 等仅支持 PCIe 2.0 的老平台填 `3`（保守取下限），
> 并列入 `estimated`。

## 8. 给子任务（并行执行）的说明模板

如果你打算用并行子任务来补数据，每个子任务必须遵守：

```
【硬性要求】
1. 先读 schema/fields.js，只用该品类已定义的字段名（逐字匹配，不可自创）
2. 先读 src/core/enums.js，枚举取值大小写敏感，socket 为 'LGA1151-2' 带引号
3. 先读 data/<category>.json，避免 id 与型号重复
4. 只在数组末尾追加，不修改/删除任何已有记录
5. 不写 price 字段（本期不做价格）
6. 枚举越界（如 pcieVersion 填 2）会导致校验失败

【数据可信度】
7. maxPower 填真实峰值功耗（Intel PL2 / AMD PPT），不是 TDP
8. 非官方核实的数据必须在 estimated 里列出字段名
9. 不确定就留空，不要瞎猜

【显卡特别要求】
10. chipset 是归并键，必须准确（如 "GTX 1660 SUPER" 不能写成 "GTX1660S"）
11. length_mm 必须真实反映该型号形态；同一 chipset 的变体长度应有差异
12. pcieVersion 只有 3/4/5 三个枚举值

【主板特别要求】
13. formFactor 枚举为 E-ATX / ATX / M-ATX / Mini-ITX
14. 归并键是 chipset·formFactor，不要把不同板型混在一起
15. memoryType 必须与同插槽的 CPU 兼容（否则 E3 报错）

【自检】
16. 运行 node tools/validate-data.mjs <category> 直到 0 错误、记录数达标
17. 不要修改校验脚本、fields.js、enums.js 来迁就数据
```
